# arrow_proto

A protobuf mirror of Arrow's filesystem option types, so object-store settings
can be expressed in configuration. Package is `pb.arrow.*`, built as
`payload_manager::arrow_proto`.

| Proto | Messages |
|---|---|
| `arrow_storage.proto` | `ObjectStorageConfig`, `FileSystemOptions` (oneof), `FileSystem` enum, `Compression` enum |
| `arrow_fs_s3.proto` | `S3Options`, `S3ProxyOptions`, `S3CredentialsKind` |
| `arrow_fs_gcs.proto` | `GcsOptions`, `GcsCredentials` |
| `arrow_fs_azure.proto` | `AzureOptions`, `AzureCredentials`, `AzureCredentialKind` |
| `arrow_fs_hdfs.proto` | `HdfsOptions`, `HdfsConnectionConfig` |

## Why it sits here rather than under `config/`

**It mirrors an external shape.** These messages track Arrow's own
`arrow::fs::*Options` structs; they describe nothing about this service. Keeping
them in their own subtree makes that obvious, and is a standing reminder not to
rename fields to suit local taste — they are meant to track upstream.

**Namespace hygiene.** The `pb.` prefix keeps the generated C++ out of Arrow's
real namespace, so `pb::arrow::fs::s3::S3Options` (the proto mirror) and
`arrow::fs::S3Options` (the live C++ struct) coexist without collision.
`internal/storage/common/arrow_utils.cpp` converts between them.

**Its own library.** `payload_manager::config_proto` depends on it PUBLIC,
because `config.proto` imports `arrow/arrow_storage.proto` for
`StorageConfig.object`. Anything that only needs the filesystem options can link
`arrow_proto` alone.

## Namespace mapping

```
pb.arrow.storage.ObjectStorageConfig  -> pb::arrow::storage::ObjectStorageConfig
pb.arrow.storage.FileSystemOptions    -> pb::arrow::storage::FileSystemOptions
pb.arrow.fs.s3.S3Options              -> pb::arrow::fs::s3::S3Options
pb.arrow.fs.gcs.GcsOptions            -> pb::arrow::fs::gcs::GcsOptions
pb.arrow.fs.azure.AzureOptions        -> pb::arrow::fs::azure::AzureOptions
pb.arrow.fs.hdfs.HdfsOptions          -> pb::arrow::fs::hdfs::HdfsOptions
```

## Build

Generated by the single `generate_protos` target in `proto/CMakeLists.txt` along
with everything else under this root — one protoc invocation, three libraries.
There is no separate codegen pass for this directory.

Which filesystem backends are actually usable depends on how the installed Arrow
was built; `PAYLOAD_MANAGER_ARROW_GCS`, `_AZURE` and `_HDFS` in the root
`CMakeLists.txt` gate the corresponding code in `arrow_utils.cpp`. S3 is assumed
present and is checked at configure time.
